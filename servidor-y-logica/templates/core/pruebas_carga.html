Diagnóstico del Servidor de Desarrollo

El servidor utilizado para estas pruebas corresponde al servidor de desarrollo de Django (manage.py runserver). Es monohilo y no realiza balanceo de peticiones por defecto.

  • Límite de Sockets: El backend responde a una tasa excelente (<20ms) bajo baja concurrencia, pero se satura físicamente (connection reset) al superar las 30 peticiones concurrentes.
  • Recomendación Crítica: Para entornos de producción es requerido migrar a un servidor multiproceso/hilos como Gunicorn o Waitress, gestionado bajo un balanceador Nginx.
  • Eficiencia del Código: Dado que las latencias p95 capturadas son extremadamente bajas, el tiempo invertido en la base de datos Supabase es mínimo y el enrutamiento de Django es sumamente óptimo.
