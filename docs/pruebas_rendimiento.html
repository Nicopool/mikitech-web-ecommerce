Estrategia de Mitigación y Escalabilidad

Para evitar caídas y fallos en producción cuando se superen los 30 usuarios simultáneos, se propone la siguiente arquitectura:

1
Reemplazo del Servidor HTTP de Desarrollo

Sustituir manage.py runserver en producción por un servidor WSGI de grado industrial como Gunicorn o Uvicorn. Esto permite levantar múltiples trabajadores (workers) y subprocesos para atender solicitudes concurrentemente.

2
Implementación de Servidor Web Inverso (Nginx)

Usar Nginx como proxy inverso frente a Gunicorn. Nginx gestionará de manera ultraeficiente la entrega de archivos estáticos (CSS, JS, imágenes), liberando a Django de esa carga para enfocarse únicamente en peticiones dinámicas.

3
Pooling de Conexiones de Base de Datos

Habilitar el pool de conexiones a la base de datos de Supabase PostgreSQL mediante PgBouncer (puerto 6543) para evitar agotar las conexiones disponibles cuando cientos de hilos concurrentes hagan consultas simultáneas.

4
Políticas de Rate Limiting y Control de Cola

Configurar límites de peticiones por segundo por dirección IP en Nginx para mitigar posibles ataques de denegación de servicio (DoS) y asegurar un acceso equitativo al ancho de banda del servidor.
